# IPL Player Ranking Methodology

The official leaderboard, role-specific lists, exports, and API are generated by
`engine/ipl_player_ranking.py` from the supplied IPL ball-by-ball and match
datasets. No external player statistics are used.

## Official category weights

| Category | Weight |
| --- | ---: |
| Traditional Performance Statistics | 15% |
| Match Situation & Pressure Performance | 25% |
| High-Impact & Match-Winning Performance | 17% |
| Important Match Performance | 15% |
| Consistency & Adaptability | 10% |
| Advanced Game Intelligence & Fielding | 8% |
| **Six-category subtotal** | **90%** |

These six configurable weights are not reassigned when data is missing. The
remaining 10% is reserved for one standalone, role-specific rate metric; it is
not another category.

## Final score frameworks

| Framework | Six categories | Standalone rate component | Total |
| --- | ---: | ---: | ---: |
| Batter | 90% | Overall batting strike rate: 10% | 100% |
| Bowler | 90% | Overall bowling economy: 10% | 100% |
| All-rounder | 50% of batter score + 50% of bowler score | Both are inherited through that blend | 100% |

For each standalone component, the underlying rate is normalized to 0–100
using role-aware 5th–95th percentile clipping. Higher strike rate is better;
lower economy is better. The overall rate metrics are excluded from all six
categories, so neither is counted twice. Contextual and phase-specific rate
metrics remain distinct parameters in their relevant categories.

The supplied dataset has no official player-role label, so the all-rounder
pool is operationally inferred only when both separate role scores are
available. Its score is the arithmetic mean of the independently calculated
batter and bowler scores; this makes the effective all-rounder contribution 5%
from each standalone rate component. This is a scoring-path classification, not
an official cricket role designation. The Top 10 Batter and Bowler lists
retain their existing minimums of 1,000 runs and 50 wickets; the All-Rounder
list requires both role scores.

## Category parameters

| Category | Batting parameters | Bowling parameters | Shared / fielding parameters |
| --- | --- | --- | --- |
| Traditional | Runs per match, average, 50s/100s per innings, boundary-run percentage, fours/sixes per innings | Wickets per innings, bowling average, bowling strike rate, dot-ball percentage | Catches, run-outs, stumpings (coverage-only when unsupported) |
| Match Situation & Pressure | SR at required run rate ≥12 and <6, SR with ≤4 wickets in hand, close-finish runs, final-over SR, recovery SR | Economy at required run rate ≥12 and <6, wickets with ≤4 wickets in hand, close-finish and final-over economy, low-total defenses | — |
| High-Impact & Match-Winning | Runs in wins, final overs scoring 17+ runs, Player of the Match rate | Wickets in wins, sub-10 final-over defenses, well-set batter dismissals, partnership breaks, Player of the Match rate | Runs saved (coverage-only when unsupported) |
| Important Match Performance | Runs and strike rate in supplied knockout/important matches | Wickets per innings and economy in supplied knockout/important matches | Important-match contributions; must-win labels are unavailable unless supplied |
| Consistency & Adaptability | Last 5/10 appearances, multi-season consistency, home/away balance, strong-opposition runs, batting positions, pitch adaptability | Last 5/10 appearances, multi-season consistency, home/away balance, strong-opposition wickets, bowling phases, pitch adaptability | — |
| Game Intelligence & Fielding | Powerplay/middle/death and pace/spin strike rates; batting failure rate | Powerplay/middle/death and batter-handedness economy; expensive-spell rate | Dropped catches (coverage-only when unsupported) |

Each metric belongs to one category only. A role path averages its supported
normalized metrics within the applicable role group, combines role groups using
the role distribution shown in the website methodology table, then applies the
category's official weight. The six category weights total 90% in each role
framework.

## Data integrity and normalization

The pipeline filters the attached delivery data to `IPL YYYY` competitions and
uses recorded match-stage, result, winner, Player-of-the-Match, delivery, run,
wicket, phase, required-rate, and batter-handedness fields when available.
Derived measures are explicitly labelled as derived statistics or derived
estimates.

Metrics are normalized by role, lower-is-better metrics are inverted, and
sample thresholds and shrinkage reduce unstable small-sample extremes. Missing
values are not imputed. An unavailable category or standalone rate contributes
no points; its fixed weight is not redistributed. Coverage reflects missing
expected metrics, and profiles with incomplete coverage or fewer than five
matches are flagged. Unsupported fielding metrics remain unavailable rather
than being treated as zero-valued performance.

## Master scores

Consistency, Pressure Performance, and Match Impact are independently
normalized indicators. They do not add to any final score.

## Rebuild and validation

Run `npm run build:rankings` to regenerate the API JSON and CSV leaderboards.
Run `python -m unittest tests.test_evaluation_engine -v` to validate the 90%
category subtotal, both 90/10 role frameworks, all-rounder blending, score
bounds, normalization, missing-data behavior, ordering, and master-score
separation.
